# aagent 0.1.1

The first functional release of `aagent` provides one command for running an
already-installed CLI coding agent headlessly. It supports Codex CLI, Claude
Code, OpenCode, Gemini CLI, and Amp on macOS, Linux, Windows Git Bash or WSL,
and PowerShell 7.

Version `0.1.1` supersedes a never-finalized `0.1.0` prerelease after its
Windows Git Bash remote-install check found a native-path checksum issue. The
installer now normalizes Windows drive-letter destinations before staging and
verifying downloads.

## Included

- explicit provider selection or deterministic automatic selection;
- preference for confirmed subscription-backed usage over direct metered API
  usage, using only passive non-secret local evidence;
- provider-native model and argument forwarding;
- prompt, stdin, working-directory, output, signal, and exit-status fidelity;
- non-mutating `providers`, `doctor`, and redacted `--dry-run` diagnostics;
- child-only Claude and Codex authentication policy adjustments;
- atomic Bash and PowerShell installers backed by `SHA256SUMS`; and
- cross-platform fake-provider tests plus credential-free compatibility drift
  checks for current Tier 1 CLI command surfaces.

## Install

Use the version-pinned commands in the
[README](https://github.com/AnandChowdhary/aagent/tree/v0.1.1#install). The
release contains `aagent.sh`, `aagent.ps1`, `install.sh`, `install.ps1`, and a
checksum manifest covering all four scripts.

## Known limitations

- Coding agents must already be installed and authenticated; `aagent` does not
  install or sign in to them.
- Tier 2 providers, quota-aware routing, normalized structured output, and
  portable sessions remain deferred.
- Amp does not expose a documented general per-run model flag.
- The wrapper preserves each selected provider's native permission defaults
  and never claims those defaults are read-only.
- Passive evidence may be unavailable or ambiguous and then degrades to
  `unknown`; `aagent` does not inspect tokens, query billing APIs, or guess
  remaining quota.
- Windows PowerShell cannot synthesize a portable console Ctrl-C in CI, so its
  contract test preserves interrupt-like native statuses while normal launches
  remain attached to the caller's console.

No paid or model prompts were sent by release CI. Current provider help and
version surfaces were checked without credentials; functional provider runs
were verified with deterministic fake executables.
