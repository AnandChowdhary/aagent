# Goose CLI revalidation

Status: Normative implementation input for P12B-01
Research snapshot: 2026-08-05

This revalidation freezes the current public interface that the `goose`
adapter may use. Since the initial survey, Goose has moved from Block to the
[Agentic AI Foundation](https://github.com/aaif-goose/goose), a Linux
Foundation project. The adapter follows that maintained upstream.

## Evidence and method

Only first-party Goose sources were used:

- the [Goose repository](https://github.com/aaif-goose/goose);
- the [headless Goose tutorial](https://github.com/aaif-goose/goose/blob/v1.45.0/documentation/docs/tutorials/headless-goose.md);
- the [environment-variable guide](https://github.com/aaif-goose/goose/blob/v1.45.0/documentation/docs/guides/environment-variables.md);
- the [provider guide](https://github.com/aaif-goose/goose/blob/v1.45.0/documentation/docs/getting-started/providers.md);
- the [CLI-provider guide](https://github.com/aaif-goose/goose/blob/v1.45.0/documentation/docs/guides/cli-providers.md);
- the [ACP-provider guide](https://github.com/aaif-goose/goose/blob/v1.45.0/documentation/docs/guides/acp-providers.md); and
- the tagged [CLI](https://github.com/aaif-goose/goose/blob/v1.45.0/crates/goose-cli/src/cli.rs)
  and [configuration](https://github.com/aaif-goose/goose/tree/v1.45.0/crates/goose/src/config)
  source.

The current stable macOS arm64 archive for Goose `1.45.0` was downloaded and
its published checksum was verified:

```text
90c50d653d7fd978ec5d436b548eca8613dc2d26d028b486b7c52271267ec500  goose-aarch64-apple-darwin.tar.gz
```

The isolated binary was invoked only for `--version` and `run --help`. It
reported `1.45.0`. No provider check, authentication flow, extension, session,
tool call, or model prompt was started. In particular, `goose info --check`
was not used because upstream documents and implements it as a real model
request.

## Verified command contract

| Concern | Current first-party behavior | `aagent` consequence |
| --- | --- | --- |
| One shot | `goose run --text PROMPT` runs a supplied instruction without the interactive UI. | Prompt-only starts with `goose run --text` and preserves the native exit status. |
| Standard input | `goose run --instructions -` reads instructions from stdin. | Stdin-only uses that form. Prompt plus stdin is combined with the documented wrapper separator and sent through `--instructions -`. |
| Model | `--model ID` selects a model for the run; `GOOSE_MODEL` is the environment equivalent. | Wrapper `--model` maps directly to the flag. Model IDs remain provider-specific opaque data. |
| Output | `--output-format` accepts `text`, `json`, or `stream-json`. | Text remains native passthrough; the structured modes are capability metadata until normalization is implemented. |
| Sessions | `--name`, `--resume`, `--session-id`, and `--no-session` control native sessions. | Native session options remain explicit post-`--` arguments; the wrapper generates none. |
| Provider | `--provider` and `GOOSE_PROVIDER` override the configured active provider. | Provider routing remains owned by Goose. `aagent` reads only the selected non-secret provider ID for funding classification. |
| Exit | Goose returns a native process status; no complete stable numeric taxonomy is published. | Preserve stdout, stderr, signals, and the exact native status. |

## Permission boundary

Goose currently defaults `GOOSE_MODE` to `auto` in upstream source. Modes and
extension permissions are native Goose policy, not a portable safety promise.
`aagent` must never generate or set `GOOSE_MODE`, an auto-approval option,
extension flags, provider configuration, or a profile. It forwards native
arguments supplied explicitly after `--`, and otherwise leaves installed Goose
configuration untouched.

The frozen generated launch plans are:

```text
goose run --text PROMPT
goose run --instructions -
```

## Authentication and funding evidence

Goose stores the selected provider as top-level `active_provider` in its YAML
configuration, with legacy `GOOSE_PROVIDER` as a fallback and the environment
variable taking precedence. `GOOSE_PATH_ROOT`, when absolute, relocates the
configuration root. Otherwise the supported locations are:

- macOS: `~/Library/Application Support/Block/goose/config.yaml`;
- Linux: `${XDG_CONFIG_HOME:-~/.config}/goose/config.yaml`; and
- Windows: `%APPDATA%/Block/goose/config/config.yaml`.

Secrets live separately in the OS keyring or `secrets.yaml`. `aagent` never
opens either. It reads at most 64 KiB of the selected configuration and accepts
only a short top-level scalar provider ID. Malformed, oversized, or ambiguous
configuration degrades to unknown.

The selected provider determines the funding path:

| Selected provider | Classification |
| --- | --- |
| `claude-acp` or `claude-code` | Inherit the safe Claude probe, including subscription versus metered routing. |
| `codex-acp` or `codex` | Inherit the safe Codex account probe and child API-key shadowing plan. |
| `gemini-cli`, `cursor-agent`, `copilot-acp`, or `amp-acp` | Inherit the corresponding adapter's bounded passive evidence. |
| `chatgpt_codex`, `gemini_oauth`, or `github_copilot` | `included_account`; configuration proves the account route but not a plan tier or remaining allowance. |
| `ollama`, `lmstudio`, `atomic_chat`, `omlx`, or `local_inference` at loopback | `local`, eligible automatically only with `allow_local=true`. A configured remote endpoint is funding-unknown. |
| A known direct API provider | `payg_byok`; readiness remains based on documented environment-variable presence rather than secret values. |
| A custom provider | Parse only `base_url`, `api_key_env`, and `requires_auth`: loopback is opt-in `local`, authenticated remote is `payg_byok`, and unauthenticated remote is unknown. |
| Any unknown provider ID | Ready with funding unknown; never guess from its name. |

Custom provider definitions live under `config/custom_providers/ID.json`.
Their credential field names an environment variable; only that variable's
presence is tested. Raw values, arbitrary JSON fields, provider responses, and
all keyring content remain outside the wrapper boundary.

Nested CLI and ACP routes inherit the underlying provider's authentication
policy as well as its funding class. For example, Goose using `codex-acp` with
a confirmed ChatGPT account may suppress a shadowing `CODEX_API_KEY` in the
Goose child under `prefer-included`. This projection never modifies the parent
environment.

## Frozen P12B-01 implementation requirements

The implementation PR must:

1. activate `goose` without changing registry or popularity order;
2. build the prompt and stdin launch plans as arrays and map `--model` directly;
3. preserve cwd, output streams, signals, and the native exit status;
4. generate no approval, mode, extension, provider, profile, session, or structured-output option;
5. resolve only documented config locations and parse only bounded selected-provider fields;
6. inherit safe underlying-provider funding and child authentication policy without executing the nested provider;
7. classify known included, local, BYOK, custom, and unknown routes conservatively;
8. never open Goose secrets, the keyring, or invoke `goose info --check`;
9. add Bash and PowerShell adapter, discovery, probe, selection, introspection, security, compatibility, and documentation fixtures; and
10. install the current stable official Goose distribution in credential-free GitHub Actions and inspect only version/help output.

No unresolved interface question blocks P12B-01. Exact plan tier and remaining
allowance are unavailable for Goose-owned account providers and stay unknown;
quota-aware balancing remains a future backlog item.
