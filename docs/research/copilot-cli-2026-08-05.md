## Verified command contract

| Concern | Current first-party behavior | `aagent` consequence |
| --- | --- | --- |
| One shot | `copilot -p PROMPT` and `copilot --prompt PROMPT` execute programmatically and exit after completion. | The adapter uses an argument array beginning with `--prompt PROMPT`; it never enters the interactive UI. |
| Clean text | `-s` or `--silent` emits only the agent response and omits usage/session metadata. | Text passthrough uses `--silent` so wrapper stdout remains the provider's answer. |
| Clarification | `--no-ask-user` disables the `ask_user` tool. | The adapter adds it for a genuinely headless run; it does not grant any tool permission. |
| Input | Piped input is supported only as an alternative to `--prompt`; when both are present, the pipe is ignored. | Prompt-only, stdin-only, and prompt-plus-stdin inputs are resolved by `aagent` into one prompt argument. The adapter must not depend on provider stdin when `--prompt` is present. |
| Model | `--model ID` selects a model. Precedence is custom-agent model, CLI flag, `COPILOT_MODEL`, settings, then provider default. | A wrapper `--model` value maps directly to native `--model`; identifiers remain provider-specific. |
| Output | Text is the default. `--output-format json` emits JSONL, one object per line. | Tier 2 text mode remains native passthrough. JSONL is capability metadata for Phase 14, not silently enabled. |
| Sessions | `--resume=ID` and `--continue` exist, and prompt-mode summaries expose a session ID. | Session behavior remains deferred to Phase 14 and is not inferred from other providers. |
| Working directory | `-C DIRECTORY` changes directory before other work. | The shared launcher continues to set the child cwd directly; no duplicate `-C` is required. |
| Exit | GitHub documents that prompt mode exits, but publishes no stable numeric exit-code taxonomy. The verified binary returned `0` for help/version and `1` for an unknown option or missing prompt value. | Preserve the native status exactly. Do not map Copilot status `1` to a wrapper-owned meaning or assume every runtime failure uses it. |

## Permission boundary

Copilot CLI exposes two separate layers:

- `--available-tools` and `--excluded-tools` limit tools visible to the model;
- `--allow-tool` and `--deny-tool` grant or deny runtime permission for matching
  tools.

The native `--allow-all-tools`, `--allow-all-paths`, `--allow-all-urls`,
`--allow-all`, and `--yolo` forms broaden permission. `--deny-tool` takes
precedence over allow rules. `aagent` must add none of these permission flags.
Users may pass native controls explicitly after the wrapper's `--` separator,
and the generic permission audit must continue to reject any generated bypass.

`--no-ask-user` is retained in the base headless plan because it disables a
clarification tool; it neither approves filesystem/shell tools nor weakens a
deny rule. A run that needs ungranted native permission may fail, which is safer
than silently escalating it.

## Authentication and funding evidence

### GitHub-backed path

For GitHub-hosted Copilot models, documented credential precedence is:

1. `COPILOT_GITHUB_TOKEN`;
2. `GH_TOKEN`;
3. `GITHUB_TOKEN`;
4. OAuth stored by `copilot login` in the operating-system keychain; and
5. the GitHub CLI token fallback.

Environment variables silently override stored OAuth. Supported GitHub tokens
still require the correct permission and account policy. The command list has
`login`, but no non-mutating `status` or entitlement command. `gh auth status`
only establishes GitHub CLI authentication; it does not prove a Copilot
license, CLI policy, or remaining allowance. `aagent` therefore must not invoke
`login`, read the Copilot keychain/config token, or send a prompt to confirm
entitlement.

GitHub token-variable presence may be reported as low-confidence auth evidence
without reading its value. Executable presence, GitHub CLI login, or a hidden
OAuth token alone cannot be upgraded to `ready` or to a confirmed included
plan. A GitHub-backed candidate with no safe entitlement evidence remains
`unknown` and can still be chosen explicitly.

### BYOK path

`COPILOT_PROVIDER_BASE_URL` activates a custom provider. The model comes from
`--model`, `COPILOT_MODEL`, or provider-model variables. Supported types are
OpenAI-compatible, Azure OpenAI, and Anthropic. Credentials may be supplied by
`COPILOT_PROVIDER_API_KEY` or `COPILOT_PROVIDER_BEARER_TOKEN`; a local endpoint
such as Ollama may require neither. BYOK model requests take precedence over
the GitHub-backed model path regardless of GitHub authentication status.

The adapter's funding classification must describe the path that the child
will actually use:

| Evidence visible without secret access | Funding classification |
| --- | --- |
| BYOK base URL is loopback/local and no provider credential variable is present | `local`, subject to `allow_local`; endpoint parsing must reject embedded credentials and never print the raw URL. |
| BYOK base URL plus API-key or bearer-token variable presence | `payg_byok`; inspect presence only, never the value. |
| Remote BYOK base URL without a recognized credential signal | `unknown`; do not guess free or metered. |
| GitHub token-variable presence without BYOK | GitHub account path with low auth confidence; funding is no stronger than `included_account`, never `included_confirmed`. |
| Only executable or possible stored OAuth/GitHub CLI fallback | Authentication and funding `unknown`. |

Provider headers may contain credentials and must never be read or emitted.
Provider type, endpoint class, model-source name, and credential-variable names
may be disclosed only through the existing redacted diagnostic vocabulary.

## Frozen P12A-02 implementation requirements

The implementation PR must:

1. activate the existing `copilot` registry entry without changing stable
   registry order;
2. build `copilot --prompt PROMPT --silent --no-ask-user`, inserting
   `--model ID` and user-native arguments as array elements;
3. combine stdin with the prompt before launch because native prompt mode
   ignores piped input when both are supplied;
4. preserve cwd, stdout, stderr, signals, and native status through the shared
   launcher;
5. add no native permission grant or availability expansion;
6. classify BYOK before GitHub-backed auth, inspect credential variables by
   presence only, and leave unverifiable stored entitlement unknown;
7. keep JSONL and sessions disabled unless a later explicit surface requests
   them;
8. expose the permission and funding caveats in `providers`, `doctor`, README,
   and dry-run output without secrets; and
9. add Bash and PowerShell adapter, discovery, selection, auth, introspection,
   security, compatibility, and documentation fixtures without a real prompt.

No unresolved interface question blocks P12A-02. Numeric provider errors remain
opaque by design and are tested through exact status passthrough rather than a
Copilot-specific remapping.
